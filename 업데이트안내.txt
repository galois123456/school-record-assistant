생기부 작성 도우미 웹 ver3.16

## 3.16 서버 저장 안정화 — 적용 순서

1. 현재 앱에서 통합 백업을 내려받습니다.
2. Supabase SQL Editor에서 `supabase/upgrade-3.16.sql` 전체를 실행합니다. 기존 생기부 자료와 다른 앱의 테이블은 삭제하지 않습니다. 처음 설치하는 경우 `supabase/schema.sql`을 실행하세요.
3. `school-record-assistant` 폴더 내용으로 GitHub의 기존 파일을 덮어쓰고 Vercel 배포 완료를 확인합니다. 환경변수는 기존 값을 유지합니다.
4. 열어 둔 이전 버전 탭을 닫고 웹 3.16으로 다시 접속합니다. ‘지금 저장’을 눌러 실제 서버 저장 완료를 확인합니다.

입력 후 약 5초 동안 변경이 없으면 자동 저장합니다. 자동 저장 요청은 최소 10초 간격으로 제한합니다. 입력은 계속 기기에 임시 보관되며 지금 저장 버튼은 즉시 요청합니다.
실패 후 자동 재시도는 10초 → 30초 → 60초 간격으로 최대 3회입니다. 이후 자동 재시도를 중단하고 오류를 표시합니다. 저장 항목 오류·권한 오류·함수 미설정은 자동으로 반복하지 않습니다. 원인을 해결하고 지금 저장을 눌러 다시 시도하세요.
수정 내용이 없는 수동 저장도 실제 서버 응답을 확인하지만 자료·revision·updated_at은 다시 기록하지 않습니다. 상단 저장 완료 시각은 응답을 확인한 시각입니다.

이번 수정으로 실제 Supabase 장애 원인이 확인된 것은 아닙니다. 프로젝트를 다시 열어 정상화된 것만으로 원인을 확정할 수 없습니다. 재발하면 오류 발생 시각, 앱의 오류 문구, Supabase Postgres/API 로그와 자원 사용량을 함께 확인해야 합니다. 인증 토큰이나 학생 자료는 공유하지 마세요.
