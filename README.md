# 생기부 작성 도우미 · 웹 ver3.17

## 3.17 업데이트

수행 평가 전체 명단 인쇄에 반 제목 바로 아래 공통 문구를 표시합니다. 마지막 입력 후 3초가 지나면 자동 저장을 요청합니다. 진행 중인 요청이 있으면 최신 변경을 모아 완료 후 남은 3초 대기시간을 지켜 보냅니다. 실패 시 10초 → 30초 → 60초로 최대 3회 재시도하며, 추가 입력도 이 대기시간과 중단 상태를 해제하지 않습니다. 변경 없는 자동 확인은 최소 10초 간격을 유지합니다. 지금 저장은 수동 재시도할 수 있습니다. 서버 저장 완료는 응답을 받은 뒤 표시합니다.

3.16 SQL을 적용했다면 추가 SQL은 필요 없습니다. 이전 버전에서는 supabase/upgrade-3.16.sql을 실행하세요. 신규 설치는 supabase/schema.sql을 사용합니다.

## 기존 웹 업데이트

1. 전체 설정에서 통합 백업을 내려받습니다.
2. 3.16 SQL을 아직 적용하지 않았다면 supabase/upgrade-3.16.sql 전체를 실행합니다.
3. GitHub school-record-assistant 저장소의 파일을 덮어씁니다. Vercel 환경변수는 유지합니다.
4. 배포 완료 후 이전 탭을 닫고 웹 ver3.17로 접속하여 지금 저장을 확인합니다.

## 1. 구성과 저장 방식

| 구분 | 역할 |
| --- | --- |
| GitHub | 이 프로젝트의 소스 코드 보관 |
| Vercel | 생기부 웹사이트 배포 |
| 기존 todolist Supabase | 기존 계정으로 로그인 + 생기부 자료 저장 |
| `school_record_workspaces` | 계정마다 생기부 자료 한 묶음을 저장하는 전용 테이블 |
| `school_record_save_workspace` | 계정 확인 및 저장 버전 비교를 수행하는 전용 함수 |

todolist의 테이블과 데이터는 이 앱에서 사용하지 않습니다. 제공한 SQL도 생기부 전용 테이블·함수·정책만 만들거나 갱신합니다. 계정과 비밀번호는 공유하므로, 이 앱에서 비밀번호를 변경하면 todolist 로그인에도 같은 새 비밀번호를 사용합니다. 사이트 주소가 다르면 로그인 상태가 자동으로 공유되지는 않습니다. 각 사이트에서 한 번씩 로그인하세요.

네 화면의 기능, 종합·국어·영어·수학·사회·과학 카테고리, 철수·영희 예시, 문장 변수와 조사 처리, 최종 완료 잠금, 실행 취소·다시 실행, 입력칸 높이, 바이트 설정, 상벌점, 통합 백업·복원, PC·모바일 반응형을 유지했습니다.

## 2. 기존 todolist Supabase에 테이블 추가

1. Supabase 대시보드에서 **기존 todolist 프로젝트**를 엽니다.
2. **SQL Editor → New query**를 선택합니다.
3. 이 폴더의 `supabase/schema.sql` 전체 내용을 붙여 넣고 **Run**을 누릅니다.
4. Table Editor에서 `school_record_workspaces`가 생겼는지 확인합니다. 처음에는 빈 테이블입니다.

기존 todolist SQL을 다시 실행하거나 테이블을 지울 필요가 없습니다. 이 SQL은 같은 프로젝트에 다시 실행할 수 있습니다. 새 사용자를 만들지 않으며 기존 사용자 목록도 유지합니다.

## 3. GitHub에 올리기

별도의 GitHub 저장소(예: `school-record-assistant`)를 만드는 방법을 권장합니다.

1. ZIP을 압축 해제합니다.
2. `school-record-assistant` 폴더 **안의 내용**을 새 저장소 루트에 올립니다.
3. 저장소 첫 화면에서 `package.json`, `package-lock.json`, `vercel.json`, `README.md`, `src`, `scripts`, `supabase`, `tests`가 보여야 합니다.
4. Commit 합니다.

`.env.example`, `.gitignore`, `.github`는 숨김 파일/폴더라 파일 탐색기에서 안 보일 수 있습니다. Git을 이용하면 함께 추가됩니다. 웹 업로드로 숨김 파일을 빼먹어도 기본 배포는 가능하지만 `.env`나 비밀 키는 올리지 마세요. `node_modules`와 `dist`는 업로드하지 않습니다.

기존 todolist 저장소를 덮어쓰지 마세요. **Supabase 프로젝트만 공유**하고 GitHub 저장소와 Vercel 사이트는 별도로 만듭니다. 기존 저장소의 하위 폴더에 넣는 경우 Vercel의 Root Directory를 해당 폴더로 지정합니다.

## 4. Vercel 배포

1. Vercel에서 **Add New → Project**로 새 GitHub 저장소를 가져옵니다.
2. **Framework Preset: Other**를 선택합니다.
3. Root Directory는 `package.json`이 있는 위치로 설정합니다.
4. 다음 환경변수 두 개를 추가합니다. **기존 todolist 프로젝트의 Supabase 값**을 사용하세요.

| 환경변수 이름 | 넣을 값 |
| --- | --- |
| `PUBLIC_SUPABASE_URL` | 기존 프로젝트 URL. 예: `https://abcdefgh.supabase.co` |
| `PUBLIC_SUPABASE_ANON_KEY` | 같은 프로젝트의 publishable key (`sb_publishable_…`) 또는 legacy `anon` key |

Supabase 프로젝트의 Connect 또는 Settings → API Keys에서 확인합니다. **`service_role`이나 `sb_secret_…` 비밀 키는 사용하지 않습니다.** 공개 키가 브라우저에 포함되는 구조이며 자료 접근은 로그인과 RLS로 제한합니다.

5. 아래 값은 `vercel.json`에서 지정되어 있습니다. 수동 설정이 표시되면 일치시키세요.

| 설정 | 값 |
| --- | --- |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | 22 이상 |

6. **Deploy**를 누릅니다. 배포가 끝나면 Production 주소를 복사합니다. 예: `https://school-record-assistant.vercel.app`.

환경변수를 나중에 수정했다면 **Redeploy**해야 적용됩니다. Preview 배포를 사용하려면 그 환경에도 두 변수를 설정하세요.

## 5. Supabase 인증 주소 추가 — 기존 설정 유지

기존 todolist 프로젝트의 **Authentication → URL Configuration**을 엽니다.

- **Site URL:** 기존 todolist 주소를 그대로 둡니다.
- **Redirect URLs:** 기존 목록을 유지하고 생기부 Production 주소를 아래처럼 **추가**합니다.

```text
https://school-record-assistant.vercel.app/
```

위 주소를 실제 배포 주소로 바꾸세요. 마지막 `/`까지 넣습니다. 앱은 이메일 인증·비밀번호 재설정 시 현재 사이트 주소를 명시적으로 전달합니다. 개발할 때만 아래 주소를 추가합니다.

```text
http://localhost:5173/
```

기존 이메일 템플릿을 기본 `{{ .ConfirmationURL }}` 링크로 사용 중이면 그대로 사용합니다. 템플릿의 인증 링크를 todolist 주소로 직접 고정해 둔 경우에는 그 링크가 별도 사이트를 지원하는지 확인해야 합니다. 인증 설정과 이메일 템플릿은 두 앱이 공유하므로 임의로 전체 초기화하지 마세요.

기존 사용자는 **회원가입이 아닌 로그인**을 누릅니다. 새 계정의 회원가입·인증 메일 발송 여부는 기존 Supabase의 가입 허용 및 메일 설정을 따릅니다. Google 로그인만 사용하고 비밀번호를 만든 적이 없는 계정이라면 이 버전의 이메일·비밀번호 로그인 전에 비밀번호 재설정으로 비밀번호를 설정해야 합니다. Google 로그인 버튼은 이 버전에 포함하지 않았습니다.

## 7. 저장 상태와 여러 기기 사용

- 변경 사항은 마지막 입력 3초 후 서버 저장을 요청합니다. **상단 ‘서버 저장 완료’가 최종 기준**입니다. 편집기 안쪽 ‘저장됨’은 현재 기기에 반영된 상태를 뜻합니다.
- 로그인 상태와 미전송 자료는 현재 브라우저에도 보관됩니다. 미전송 자료는 계정별로 분리합니다. 서버 저장에 성공하면 임시 자료는 제거합니다.
- 서버에 연결하지 못하면 빈 자료를 새로 저장하지 않고 불러오기를 중단합니다.
- 이미 열어 둔 화면은 인터넷 연결이 끊겨도 작성할 수 있습니다. 연결 복구 후 재시도합니다. **오프라인 상태에서 사이트를 새로 여는 기능은 제공하지 않습니다.**
- 다른 기기에서 작성하다 돌아왔다면 **서버 자료 새로 열기**를 누르세요. 현재 기기의 변경 사항부터 저장한 뒤 최신 자료를 가져옵니다. 실시간 공동 편집이나 자동 문장 병합 기능은 아닙니다.
- 두 기기에서 같은 저장 버전을 수정하면 두 번째 저장을 중단하고 선택 창을 표시합니다. **현재 기기 자료 백업 → 서버 자료 사용** 또는 **현재 기기 자료로 서버 교체** 중 선택합니다. 교체하기 전에 백업을 권장합니다.
- 같은 브라우저의 같은 계정은 한 탭에서만 편집할 수 있습니다. HTTPS와 최신 브라우저가 필요합니다.
- 로그아웃은 현재 사이트의 현재 세션만 종료합니다. 미저장 변경 사항이 있으면 저장을 완료한 뒤 로그아웃합니다.
- 계정별 자료 한 묶음의 한도는 8MB입니다. 브라우저의 임시 저장 공간이 부족하면 화면에 별도로 알립니다. 주기적으로 통합 백업을 받으세요.

현재 구조는 **교사 한 명이 자신의 계정으로 사용하는 작업 공간**입니다. 다른 선생님은 각자 계정을 사용해야 자료가 분리됩니다. 운영자용 전체 학생 조회 화면이나 교사 간 자료 공유 기능은 포함하지 않았습니다. 공유 기기에서는 사용 후 로그아웃하세요.

## 8. 로컬 실행과 자동 검증

Node.js 22 이상 설치 후 프로젝트 폴더에서 실행합니다.

```bash
npm ci
```

`.env.example`을 `.env`로 복사하고 두 값을 설정한 다음:

```bash
npm run dev
```

`http://localhost:5173`을 엽니다. 소스를 수정했으면 서버를 중지하고 다시 실행합니다. 배포용 빌드는 `npm run build`입니다.

```bash
npm run check
npm test
```

테스트는 실제 프로젝트에 접속하지 않습니다. PostgreSQL 호환 PGlite에서 SQL을 실행해 계정 접근 제한, 쓰기 권한, 버전 충돌, 기존 일정 데이터 유지와 SQL 재실행을 확인합니다. 저장 엔진의 계정 분리·인터넷 오류·복구·저장 중 추가 편집·저장 용량 오류 및 네 편집기의 스크립트도 검증합니다. GitHub Actions에서도 동일한 검사와 가짜 공개 키를 사용한 빌드를 실행합니다.

6. 통합 백업을 내려받고 복원합니다.
7. todolist의 기존 일정·메모·시간표가 유지되는지 확인합니다.

이 배포 패키지는 코드 검사·자동 테스트·배포 빌드를 완료했습니다. **사용자 Supabase 프로젝트의 실제 로그인, 메일 발송, Vercel 운영 주소, 모바일/PC 브라우저 화면은 배포 후 확인해야 합니다.** 프로젝트 접속 정보가 제공되지 않아 실제 계정에 연결하거나 GitHub/Vercel에 게시하지는 않았습니다.

## 10. 자주 생기는 문제

| 증상 | 확인 |
| --- | --- |
| Vercel에서 환경변수 오류로 빌드 실패 | 두 변수 이름과 값 확인. 비밀 키가 아닌 공개 키 사용 |
| 테이블/함수 없음 오류 | 기존 프로젝트 SQL Editor에서 `supabase/schema.sql` 실행 여부 확인 |
| 이메일 인증 후 todolist로 이동 | 생기부 Redirect URL 추가 여부, 이메일 템플릿의 고정 주소 확인 |
| 로그인이 안 됨 | 기존 todolist 이메일·비밀번호인지, 이메일 인증 완료 여부 확인 |
| Vercel 로그인 화면이 나옴 | 배포된 Production 주소인지, Vercel Deployment Protection 설정 확인 |
| 다른 탭 사용 중 메시지 | 같은 계정의 다른 생기부 탭을 닫고 ‘다시 열기’ |
| 휴대폰에 최신 자료가 안 보임 | 원래 기기의 ‘서버 저장 완료’ 확인 후 ‘서버 자료 새로 열기’ |
| 기기 임시 자료를 읽지 못함 | 표시된 버튼으로 임시 자료를 내려받은 뒤, 기기 임시 자료만 비우고 서버에서 열기 |

# ver3.13 암호화 백업

전체 설정의 ‘🔒 통합 백업’에서 12자 이상의 별도 비밀번호를 두 번 입력한 뒤 ‘암호화 준비’ → ‘암호화 JSON 저장’을 누르세요. 복원에는 같은 비밀번호가 필요합니다. 분실한 비밀번호는 복구할 수 없습니다. 온라인 ver3.15과 오프라인 ver2.24는 같은 암호화 파일을 읽습니다. 기존 평문 JSON도 불러올 수 있습니다.

삭제·초기화·복원 전 안전 백업과 온라인 복구용 JSON에도 적용됩니다. 백업 취소 시 관련 파괴적 작업도 중단합니다. 브라우저 자동 저장·서버 자료 자체나 CSV·Markdown·TXT는 이 기능으로 암호화되지 않습니다. 자세한 백업 사용법은 **암호화백업_보안안내.md** 및 앱의 전체 설정·사용법을 확인하세요.

기존 저장 상태 수정도 포함합니다. ‘지금 저장’ 글자는 유지하며 제목 옆에서 실제 서버 응답에 따른 진행·완료·연결 오류를 확인합니다. 변경 내용 없는 수동 저장도 서버 응답을 확인합니다. 기존 Supabase SQL과 환경변수는 변경하지 않습니다.


ver3.13: 백업 안내를 기본 접힘으로 변경했습니다. 안전 백업 창의 백업하지 않음은 작업을 계속하며, 취소는 작업을 중단합니다. 일반 백업의 백업하지 않음은 파일 없이 창을 닫습니다.

모바일 UI 업데이트 ver3.13: 너비 760px 이하에서만 도구·필터·활동 카드 배치를 압축합니다. PC에서는 기존 배치로 표시합니다. 자세한 변경 사항은 업데이트안내.txt를 확인하세요.
